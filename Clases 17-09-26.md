Que pasa si un usuario desde su cuenta ejecuta la siguiente instrucción sin hacer COMMIT:

```
UPDATE hr.emp
SET salary = salary * 1.10
WHERE department_id = 60;
```

Y luego el mismo usuario ejecuta este comando:

```
SELECT employee_id, salary FROM hr.emp WHERE department_id = 60;
```

RESPONDER: ¿Ve el cambio en su propia sesión?

El mismo usuario desde otra sesión  o cualquier  otro usuario  tipee el siguiente comando:

```
SELECT employee_id, salary FROM hr.emp WHERE department_id = 60;
```

RESPONDER: ¿Se ve el cambio? 

Ahora el usuario que ejecuto el comando UPDATE debe ejecutar el siguiente comando:

```
ROLLBACK;
```

Verificar mediante el siguiente comando:

```
SELECT employee_id, salary FROM hr.emp WHERE department_id = 60;
```

¿Qué sucedió? Confirmar que el aumento desapareció.

En el siguiente ejercicio se provocará un bloqueo real. El primer usuario ejecutará sin COMMIT:

```
UPDATE hr.emp
SET salary = salary + 100
WHERE employee_id = 100;
```

Otro usuario ejecutara sin COMMIT:

```
UPDATE hr.emp
SET salary = salary + 200
WHERE employee_id = 100;
```

¿Qué pasó con esta sesión? Por que esta "colgada" esperando.
El primer usuario que realizó el UPDATE debe realizar lo siguiente:

```
COMMIT; 
```

En ese instante, la sesión del segundo usuario se "libera" y su UPDATE se completa. 
En este nuevo ejercicio se provocará un Deadlock o interbloqueo. Para ello el primer usuario ejecutará sin hacer COMMIT:

```
UPDATE hr.emp SET salary = salary + 1 WHERE employee_id = 100;
```

Otro usuario ejecutará sin hacer COMMIT:

```
UPDATE hr.emp SET salary = salary + 1 WHERE employee_id = 101;
```

Ahora el primer usuario ejecuta un comando intentando tocar la fila que esta trabajando el segundo usuario:

```
UPDATE hr.emp SET salary = salary + 1 WHERE employee_id = 101;

```

El primer usuario se  queda esperando al segundo usuario. Ahora el segundo usuario ejecuta un comando intentando tocar la fila que esta trabajando el primer usuario:

```
UPDATE hr.emp SET salary = salary + 1 WHERE employee_id = 100;
```

En ese instante Oracle detecta el ciclo y automáticamente **aborta una de las dos transacciones** con el error:

```
ORA-00060: deadlock detected while waiting for resource
```

La sesión que recibió el error debe hacer `ROLLBACK`. La otra sesión queda libre para continuar y hacer `COMMIT`.
